# GitHub Project Planning

When work or planning relates to a GitHub repository, keep the current plan in that repository's GitHub Issue rather than only in a local Markdown file.

- Keep one primary Issue per coherent goal or feature.
- Keep the Issue body as the current accepted plan, scope, acceptance criteria, open questions, and evidence links.
- Record meaningful planning changes as concise Issue comments; do not preserve obsolete alternatives in the current plan.
- Use GitHub Projects to aggregate status across repositories without duplicating each Issue's plan.
- Link implementation pull requests to their planning Issue. Treat pull requests, checks, and test output as delivery evidence.
- Commit Markdown plans only for current architecture or operating contracts. Use ADRs when decision history must remain durable.
- Load the applicable GitHub, Git, review, testing, or delivery skill before carrying out its workflow.
